## 6. 推送后的 CI 修复（2026-11-08）

推送 `0fa82fa` 后，CI run **42479038347** 的结果：静态检查、生成物一致、Content records **通过**；**Accessibility audit 失败**；其后 Data QA、性能预算、实体覆盖、Smoke、PWA 全部 `skipped`。Pages 部署本身成功（线上已是 `20261108y`）。

- 失败步骤由 check-run 注解确认，但**具体断言读不到**：Actions 日志接口要求仓库 admin 权限（返回 403），运行页的日志块也无公开入口。因此按 CI 与本机的环境差异逐项加固，而不是声称已定位某一条断言。
- 修复（提交随本文件）：
  1. **locale 未固定**：`content-check` 与 `a11y` 的所有浏览器上下文固定 `locale: "zh-CN"`。应用跟随 `navigator.language`，CI 的 en-US 会让中文断言与 AX 名称检查失效。
  2. **自动事件竞态**：审计开始即关闭 `autoEvent` 并关掉已打开的弹窗/史志，避免审计期间 app 被 `inert`、AX 树丢节点。
  3. **懒加载就绪**：AX/画布检查前等待 `map.features`、`HistoricalEntities.ready`、`HeroScenes/VariantScenes`、`#a11y-nodes`；剧场播报前等待 `#theatre-live` 有文本。
  4. **弹窗小字抽样阈值**：从 `n ≥ 4` 改为 `n ≥ 3`（弹窗自身只有三个 9.5px 选择器；第 4 个来自背后仍打开的史志面板，CI 状态不同）。
  5. **a11y 失败注解**：与 smoke/pwa 一致，失败时输出 `::error title=a11y::`，运行页可直接读到具体断言，不再需要 admin 日志。
  6. **2026 半屏余量**：第 5 行原来只剩 **0.2px** 余量，Linux 字体度量很容易掉到 4 行；行距与分类行各压缩 1px 后余量 **12.2px**。
