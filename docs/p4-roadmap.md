# P4 路线图 / Next stage roadmap

Date 2026-11-07。基于 P3 收口结果（[`p3-final-check-2026-11.md`](p3-final-check-2026-11.md)）与第二轮复盘（[`ux-review-p3-2026-11.md`](ux-review-p3-2026-11.md)）。

**P3 的核心结论**：性能、可访问性、数据与产品功能都到了"可交付"的边缘，但四件事卡住了质量——**没有真机、没有真实屏幕阅读器、场景产能没有质量门槛、来源治理缺少领域编辑**。P4 的排法是先把这四件事变成可验证的流程，再谈扩量。

优先级：**A（必须先做）** > **B（决定能不能扩量）** > **C（体验与内容增长）**。

---

## A. 真机性能与内存（P4-1，最高优先级）

**为什么**：P3 的所有性能数字都是 CDP 模拟（DPR 3 + CPU 4× + Slow 4G）。模拟能暴露代码缺陷（本轮就靠它发现隐藏画布被放大到 3,900 万×1,960 万像素），但**不能**回答低端 GPU 的栅格化开销、iOS 的内存回收、以及发热降频。

**范围**
- 设备矩阵（至少 5 台）：低端 Android（4–6GB RAM，如 Redmi/Realme 中低端）、中端 Android、iPhone SE 2022、iPhone 13/15、一台桌面 Mac/Windows；
- 指标：冷启 FCP、可交互时间、首屏传输、剧场 30 秒平均/p95 帧、`performance.memory`（Android Chrome）或 Xcode 内存仪（iOS）、画布内存、标签页是否被回收；
- 网络：真实 4G、3G、地铁/电梯弱网各一次；
- 场景：1937（密集）、2026（现代国名 + 196 国）、剧场 16 秒静态末帧、收藏 + 离线二次访问。

**验收**
- 产出 `docs/perf-devices-2026-12.md`：逐设备、逐网络列出数字与**未达标项**；
- 低端 Android 剧场平均 ≥30fps、p95 ≤40ms；冷启可交互 ≤5s（Slow 4G）；
- 无因画布/堆内存导致的标签页重载；
- 若 DPR 3 真机内存超预算：把 `map.dpr` 上限从 2 降到 1.5（已参数化，改一处）。

**风险**：需要设备或云真机账号（BrowserStack/LambdaTest）。没有账号时，本项保持"未验证"，不要用模拟结果替代。

## B. 内容与场景产能（P4-2）

**为什么**：Hero 32 / Tier B 45 已经维持两个版本没有扩量，而同家族差异只有 Hero 的 ~37%；1937–38 中国战场仍在用中世纪城墙。问题不是"数量不够"，而是**没有质量门槛与产能**。

**B1. Gate 3 前置：先修"家族套错"**
- 在 siege 家族内拆出 `urban-war`（近代巷战）：废墟立面、沙袋、铁轨、探照灯、防空；
- 把淞沪、台儿庄、武汉、百团迁到 `urban-war`，斯大林格勒同理；
- 验收：这 4–5 个事件的接触表与旧版并排，能一眼看出是 20 世纪城市战；Tier B 数量不减少。

**B2. 新家族 pilot（3 个，每个 3–5 个变体）**
- cavalry（草原/骑兵）、city（港口/集市）、disaster（火山/瘟疫/洪水）；
- 每个 pilot 先写"构图规则"（主体占比 28–35%、前景/中景/背景三层、与地图舞台的衔接），再画。

**B3. 盲测与扩量**
- 每批 ≥6 名评审、5 分制、均分 ≥4.5 且单项 ≥4 才扩量；
- 产出 `docs/tierb-gate3-review.md`；未过审的变体不进产品。
- 在 Gate 3 通过前，**Hero 不扩量**（32→60 是插画批次，需要独立预算与周期）。

**验收**：Tier B 从 45 扩到 60–80（不是 100–150）且**全部通过家族适配检查**；Hero 数量保持不变或按插画批次单独发布。

## C. 全量翻译与长文（P4-3）

**为什么**：实体标签显示覆盖 94%，但 112 条史志的 ES/FR/AR 长文为 0，409 条简要条目未扩写。

**范围**
- **P4-3a 标签收尾**：`npm run entity-i18n` 会打印"下一个该翻译的标签"；把 1500/1800 的显示覆盖从 69/86% 提到 ≥90%；
- **P4-3b 长文翻译**：优先 32 个 Hero 事件的 ES/FR/AR（每篇约 600–900 字），必须由母语者审校；`translation_status` 字段区分 human/reviewed；
- **P4-3c 简要条目扩写**：优先用户搜索高频词与 6 条路线上的节点；每条必须有 2 个可核对来源（见 D 数据治理）。

**验收**
- 32 篇 Hero 长文三语上线，`content-check` 扩展到多语言段落；
- 封面/面板在 ES/FR/AR 下不再出现"整段英文"；
- 每篇译文标注译审状态，不把机器翻译写成人工审校。

**风险**：母语审校成本高；建议先做 8 篇试点再决定节奏。

## D. 数据治理与来源（P4-4）

**为什么**：机构来源 25.1%，离 60% 很远；继续用"抓维基外链"的方式只会引入低质来源（实测混入 Internet Archive 随机快照与教师个人页）。

**范围**
1. **来源分级落到字段**：给每条 source 加 `tier`（primary/institutional/secondary/encyclopedic），而不是靠脚本按域名猜；面板"来源"区可按 tier 排序；
2. **机构来源专项**：为目标事件联系/检索博物馆、档案馆、大学专题页；优先二战（IWM、NARA、USHMM）、UNESCO 遗产、科学史（NASA、Nobel、CERN）；
3. **`npm run sources:check` 纳入发布前清单**（不进 CI），新增来源必须 200 + 标题匹配；
4. **敏感条目**：剩余 41 条逐条人工阅读并记录复核人/日期；
5. **标签位置**：为 1914–1945 的欧洲/东亚密集区做缩放分层（zoom 1.6 以上才显示次级政权），目标把"丢弃数"降 30%。

**验收**：机构来源 ≥40%（先定一个够得着的目标）；每条 source 有 tier；`data-qa` 输出敏感条目复核清单；标签丢弃数下降且有前后对比。

## E. 正式 WCAG 与屏幕阅读器（P4-5）

**为什么**：axe 0 违规只覆盖 DOM；画布地图、剧场、抽屉的真实听读体验没有验证。

**范围**
- NVDA（Windows + Chrome）与 VoiceOver（macOS/Safari、iOS Safari）各走查 6 条路径：切年份、打开事件、听完摘要与来源、关闭并回到触发点、抽屉展开/收起、迷你地图移动；
- 400% 缩放、Windows 高对比模式、`prefers-reduced-motion` 组合；
- 剧场状态（开始/暂停/结束）加 `aria-live` 播报；
- 面板关闭 28px、更多菜单 30px 的目标尺寸取舍写进文档。

**验收**：产出 `docs/wcag-audit-2026-12.md` 的实测章节（含录屏或逐条记录）；无 A/AA 失败项或有明确例外说明。

## F. CI、发布与监控（P4-6）

**范围**
- **确认 P3 的 CI 修复**：推送后如果 PWA 步骤仍失败，日志现在会打印具体检查项与 SW/缓存状态；
- 增加 **Lighthouse CI**（性能/可访问性/PWA 三项预算），失败不阻断部署但记录趋势；
- **运行时错误监控**：默认关闭、隐私友好（不采集正文/搜索词），需项目所有者决定服务与保留期；
- 发布节奏：每次 `version:bump` 后记录"发布 → 部署 → 抽查"三步，避免缓存混用；
- 可选：把 `smoke` 拆成"关键路径（<20s）"与"完整（含 16s）"，PR 只跑关键路径。

**验收**：连续 5 次发布无缓存导致的旧资源混用；CI 失败能在 1 分钟内定位到检查项；监控开关与隐私说明写进文档。

## G. 产品功能（P4-7）

按复盘中的 P1/P2 排：

1. **U11 深链年份**：打开事件记住来源年份，返回时恢复；深链应用后补一次 `syncURL`；
2. **D8 RTL 时间轴**：控件分组、方向键提示改为文字；
3. **U13 清空收藏**：二次确认或 5 秒 undo；
4. **U14 分享卡片落点**：toast 提供"打开/再下载"；
5. **U15 离线降级说明**：面板顶部提示"离线：长文与场景不可用"；
6. **D11 国家面板工具条**：分享/收藏/更多归组；
7. **U16/U17 移动端**：2026 首屏给列表一个可见入口；搜索加清除按钮。

**验收**：每条都有 smoke 或截图证据；不引入运行时依赖。

## H. 建议顺序与产出

1. **P4-1 真机矩阵**（决定性能预算）
2. **P4-2 B1 家族适配修复**（先修错再扩量）
3. **P4-6 CI 确认与监控决策**
4. **P4-5 屏幕阅读器实测**
5. **P4-4 来源分级与机构来源专项**
6. **P4-3 翻译与长文（8 篇试点）**
7. **P4-2 B2/B3 新家族 pilot 与盲测**
8. **P4-7 产品功能收尾**

**P4 完成的定义**：不是数字更大，而是——每台目标设备有数字、每个场景过审、每条来源可核对、每条路径能用屏幕阅读器走通。

---

## 不在 P4 范围（明确不做）

- 账号系统与云同步（涉及后端、隐私与运维，且与"静态站点"约束冲突）；
- 逐事件手绘插画（Hero 32→60 需独立插画预算，不在本路线）；
- 全量 1,800 条历史实体的三语翻译（边际收益低于风险，只做高频与显示标签）；
- 引入构建框架或运行时依赖。
