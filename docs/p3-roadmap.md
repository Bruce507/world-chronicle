# P3 路线图 / Next stage roadmap

Date 2026-11-07. 基于 P2 完成状态（见 `docs/p2-completion-2026-11.md`）。**2026-11-07 第一轮已完成**：P3-1/2/3/4/7 为部分完成，P3-5/6/8 为第一版；完成记录与未完成原因见 `docs/p3-completion-2026-11.md`。本文件保留原始范围与验收标准。

优先级原则：先保证“在更多设备上稳定可读”，再扩内容与场景数量，最后做产品化功能。P3-1 与 P3-5 是其他工作的基础设施。

---

## P3-1 真机性能、内存与首屏（最高优先级）

**为什么**：P2 的性能数字来自本机 Chrome（1440×900，ready 168–192ms、剧场 16.6ms/帧），未覆盖低端 Android、iOS Safari、弱网与 DPR 3。首屏仍需加载约 4.3MB 未压缩资源（gzip 约 0.8–1MB），低端设备可能明显卡顿。

**范围**
- 低端 Android（例如 4GB RAM、Snapdragon 6 系）与 iPhone SE / Safari 的首次加载、滚动、剧场帧率、内存峰值；
- 弱网（Fast 3G / Slow 4G）与冷缓存；
- DPR 3 设备的画布内存与发热；
- 事件详情按需载入的失败回退与加载态。

**验收**
- 记录 5 台设备的：FCP、可交互时间、首屏 JS/JSON 传输量、剧场 5 秒平均/p95 帧、`performance.memory`（如可用）；
- 低端 Android 剧场平均 ≥30fps、p95 ≤40ms；首屏可交互 ≤5s（Slow 4G，冷缓存）；
- 不出现因画布内存导致的崩溃或标签页重载；
- 形成 `docs/perf-devices-2026-12.md`，逐项列出设备、网络、数字与未达标项。

**风险/依赖**
- 需要真实设备或 BrowserStack/LambdaTest 账号；模拟器不能替代；
- 可能需要降低 DPR 上限、简化世界 GeoJSON、把 hero-scenes 按需加载；
- 与 P3-5（CI/监控）共享指标定义。

## P3-2 Hero / Tier B 扩量（30→60 主题，29→100–150 变体）

**为什么**：P2 把 Hero 与 Tier B 的史志补齐，但视觉覆盖仍是 32 个 Hero 条目、29 个 Tier B 变体；大量重点事件仍是通用家族场景，D2 的“三层质量断层”只缓解、未消除。

**范围**
- Gate 2：Hero 主题 30 → 60，新增主题必须通过构图/材质/叙事三项盲测；
- Gate 3：Tier B 变体 29 → 100–150，覆盖 siege / caravel / modern 之外的家族（cavalry、city、monument、revolution、disaster）；
- 统一质量门槛：场景主体占画面 28–35%、前景/中景/背景层次、材料细节、与地图舞台的衔接。

**验收**
- 盲测：每批 ≥6 名评审，5 分制，均分 ≥4.5，单项不低于 4；
- 60/60 Hero 与 100+/100+ 变体通过 16 秒静态末帧、390×844、60fps（本机）与烟雾测试；
- 新增场景不改变 521 事件 / 56 家族映射语义；
- 产出 `docs/hero-gate2-review.md`、`docs/tierb-gate3-review.md`。

**风险/依赖**
- 插画产能与评审成本高；需要先定“可接受的最低完成度”，避免为凑数降低质量；
- 依赖 P3-1 的设备基线，否则新增场景可能在低端设备上不可用；
- 需要保持资源体积可控（按需加载场景模块）。

## P3-3 历史实体名称全量多语言（1,800+ 条）与剩余长文

**为什么**：P2 已让现代国家/地区在 ES/FR/AR 下使用 Natural Earth 名称，但 1,800+ 条历史实体仍以中英为主；409 个事件仍是简要条目。用户会在 ES/FR/AR 界面看到混合语言。

**范围**
- 历史实体名称的 ES/FR/AR 翻译（优先 curated 实体与高频标签，再扩到快照实体）；
- 台湾等 curated 非主权实体的地名本地化，避免 2026 西班牙语界面出现“Taiwan Province”；
- 409 条简要条目的长文补齐，优先 featured（143 条）与用户搜索高频词；
- 翻译来源与回退规则写入数据字段（`name.es/fr/ar`、`translation_status`），不伪装成已翻译。

**验收**
- ES/FR/AR 界面中，地图标签与事件面板不再出现“同一屏三种语言”的明显断裂（允许专名保留原文）；
- 每条翻译有 `translation_status`（human/partial/machine），图例/关于页可解释；
- 新增长文全部含摘要/背景/经过/结果/参与方/2 来源，`content-check` 通过；
- 统计：完整史志 ≥250 条，实体翻译覆盖率 ≥80%（按显示频次加权）。

**风险/依赖**
- 翻译质量与史实准确性需要人工校对；机器翻译可能引入年代/地名错误；
- 数据体积增长，需与 P3-1 的按需加载配合；
- 敏感事件的翻译需保持纪念性、非煽动叙述。

## P3-4 正式 WCAG / 屏幕阅读器审计与对比度复核

**为什么**：P2 做了焦点管理、44px 覆盖层、ARIA 与 reduced-motion，但未做正式 WCAG 2.2 AA 审计，也未用 NVDA/VoiceOver 实测。8.5–10px 的小字号与低饱和色仍可能不达标。

**范围**
- WCAG 2.2 AA 全项审计（可感知、可操作、可理解、健壮）；
- NVDA（Windows/Chrome）与 VoiceOver（macOS/Safari、iOS）走查：时间轴、地图节点、面板、抽屉、搜索、更多菜单、迷你地图；
- 对比度复核（正文、地图标签、图例、按钮、焦点环），必要时提高最小字号；
- 键盘陷阱、焦点顺序、动态内容播报（年份变化、事件打开、剧场状态）。

**验收**
- 无 A/AA 级失败项；或有明确记录的例外与替代方案；
- 屏幕阅读器可完成：切年份、打开事件、听完摘要/来源、关闭并回到触发点、展开/收起抽屉、用迷你地图移动；
- 产出 `docs/wcag-audit-2026-12.md`，附每项的证据与修复状态。

**风险/依赖**
- 需要可用的屏幕阅读器环境与人工时间；
- 部分地图交互（画布节点）本质上难以完全无障碍，需要保留可聚焦覆盖层与文字替代；
- 与 P3-3 的翻译质量相关（语言标签、dir、朗读）。

## P3-5 CI（smoke + validate + build）与发布/缓存/错误监控

**为什么**：目前验证靠本地手动运行；没有 CI 会在合并前发现 521/56 映射、烟雾测试或构建回归。GitHub Pages 的缓存与版本号也靠人工维护。

**范围**
- GitHub Actions：`validate-data`、`build-data`、`build-scene-taxonomy`、`node --check`、`content-check`、`smoke`（Playwright + Chrome）；
- 构建产物一致性检查（`data_bundle.js` 与 JSON 源一致、scene_variants 与文档一致）；
- 发布流程：版本号/资源 query 自动更新、缓存头、回滚步骤；
- 错误监控：前端 `window.onerror`/`unhandledrejection` 上报（可选、隐私友好），或至少 CI 中的控制台错误检查。

**验收**
- PR 上自动运行全部检查，失败阻断合并；
- `main` 合并后自动部署 GitHub Pages，资源版本自动更新；
- 连续 5 次发布无缓存导致的旧资源混用；
- 形成 `docs/ci-release.md`。

**风险/依赖**
- 仓库需要 GitHub Actions 权限与 Playwright 浏览器安装时间；
- 烟雾测试依赖本地服务器，CI 中需启动 `python3 -m http.server`；
- 错误监控涉及隐私与第三方服务选择，默认关闭，需用户决定。

## P3-6 产品功能：收藏/书签、更多主题路线、分享卡片、PWA/离线

**为什么**：P2 的搜索、路线与深链已经形成发现闭环，但用户仍无法保存“我的时刻”、生成可分享的卡片，或离线阅读。PWA 可改善移动端回访与弱网体验。

**范围**
- 收藏/书签：本地保存事件、国家、路线与年份组合；面板入口与“我的收藏”列表；
- 更多主题路线：环境史、疾病与医学、女性与劳动、海洋史等，每条 8–12 个事件；
- 分享卡片：Canvas 生成 1200×630 图片（事件标题、年份、地点、场景缩略、来源域名），不包含长文；
- PWA：manifest、离线缓存（首屏 + 世界 GeoJSON + 已访问事件详情）、安装提示；
- 隐私：收藏与离线数据仅本地，不上传。

**验收**
- 收藏可增删、刷新保留、深链可打开；
- 每条新路线有名称/描述/事件/顺序，路线面板可用；
- 分享卡片在桌面与手机尺寸正确、文字不溢出、来源可读；
- PWA 可安装、离线打开首屏与已缓存事件，Lighthouse PWA 项通过；
- 不引入运行时依赖（可用原生 API）。

**风险/依赖**
- 离线缓存与资源版本/更新策略冲突，需要谨慎的 cache busting；
- 分享卡片涉及字体与 Canvas 文本排版，需多语言回归；
- 产品范围较大，建议拆成 P3-6a（收藏+路线）与 P3-6b（卡片+PWA）。

## P3-7 数据 QA：来源、政治敏感、标签位置

**为什么**：P2 修复了 25 条失效来源，但 226 条来源中仍有 Britannica/Wikipedia 为主的二手来源；部分历史标签位置、边界表述与敏感事件叙述需要持续复核。

**范围**
- 来源审计：每条完整史志至少 1 个机构来源（博物馆/档案馆/大学/UN），逐步替换纯百科来源；
- 政治敏感：边界、政权称谓、战争伤亡、殖民与种族议题的表述复核；台湾省数据与表述保持现状；
- 标签位置：密集欧洲、东亚、中东的历史标签碰撞与位置偏移；边缘裁切；
- 数据一致性：年份、地点、类别、视觉家族、国家代码的交叉校验；
- 建立“待复核”清单与责任人/日期。

**验收**
- 完整史志的机构来源比例 ≥60%；
- 敏感事件逐条有复核记录，叙述保持纪念性、非煽动；
- 标签碰撞率（抽样 20 个年份）低于 5%，边缘裁切为 0；
- `validate-data` 与 `content-check` 全过，新增 QA 报告 `docs/data-qa-2026-12.md`。

**风险/依赖**
- 机构来源可能需要订阅或访问限制；不能用不可达链接充数；
- 政治敏感表述需要项目所有者最终确认；
- 标签位置调整可能影响历史实体数据与地图视觉，需要与 P3-2 的场景扩量协调。

## P3-8 交互细节收口（P2 部分项）

**为什么**：P2 复审中 D4/U4（时间轴范围/刷选仍是隐藏手势）、U6（2026 手机 half 首屏事件少）、D7（8.5–10px 小字号与图例尺寸）仍为部分完成；这些不是回归，但需要单独收口。

**范围**
- 时间轴：显式范围手柄/刷选按钮，范围与步长 chip 常驻；双击时代带、Shift 刷选、Alt+滚轮都能在 UI 中找到入口；
- 2026 手机 half：现代国家区块默认折叠为一行 + “全部 196”，保证首屏 ≥5 条事件；国家/主题/搜索面板同样检查；
- 字号：正文/地图标签/图例最小 10px（地图标签建议 11px）；形状图例 9–10px；
- 与 P3-4 的 WCAG 审计共享对比度/字号结论。

**验收**
- 时间轴无需读说明即可发现“刷选/范围”；
- 2026 half 首屏 ≥5 条事件，390×844 无溢出；
- 小字号项通过 WCAG AA 或明确记录例外；
- `npm run smoke` 增加对应检查并全过。

**风险/依赖**：与 P3-4 的审计结论、P2-3 的抽屉布局相关；不要为了字号牺牲地图标签密度。

## 建议顺序

1. P3-1 设备基线（决定后续性能预算）
2. P3-5 CI（把验证自动化）
3. P3-4 WCAG 审计（把 P2 的无障碍工作收口）
4. P3-7 数据 QA（先把已有内容做扎实）
5. P3-3 翻译与长文（内容深度）
6. P3-2 场景扩量（视觉深度）
7. P3-8 交互细节收口（D4/U4/U6/D7）
8. P3-6 产品功能（在稳定基础上扩展）
