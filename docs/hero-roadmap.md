# 英雄插画路线图 / Hero Illustration Roadmap

Updated 2026-11-06. This is the master plan behind the three-tier scene system.

## 0. 一句话

**12 个试点 → 30 个 Hero 门槛 → 60 为上限选项；100–150 个参数化变体；其余约 300 个事件走 56 家族基线。** 不承诺 482 个全部独立插画级。

## 1. 为什么不做 482 个独立插画

482 个事件 × 每场景 3–5 层独立构图、建筑、人物、道具、色调，是**美术生产问题**，不是代码分支问题：

- 按每场景 1–2 个工作日估算，482 个约需 2–4 人年，且不含考据、评审、本地化、性能优化。
- 很多事件本身视觉差异不足，强行独立会变成“482 张重复堆元素”，反而降低可信度。
- 移动端资源体积、首屏与按需加载、版权/授权、长期维护都需要预算。
- 代码可以生成不同构图，但不能自动保证“插画级”。

因此采用三层：**Tier A 高峰、Tier B 中间层、Tier C 底座**。三层是叠加，不是替换。

## 2. 三层定义

| 层级 | 数量 | 定义 | 验收 |
|---|---:|---|---|
| **Tier A · Hero** | 12 → **30**（60 为上限选项） | 每个事件独立构图、独立建筑/人物/道具/色调；非模板换色 | 5 层、3 个明暗带、8 个材质区、3 种刻线技法、构图去重、史实清单、4.5/5 |
| **Tier B · 半独立** | 100–150 | 同一家族语法下的**参数化变体**：天际线、主建筑、人物组、天气、时段、色板、镜头、前景框可调 | 同家族内 A/B 可区分（7/10）；不重复标题；移动端预算；见 `variant-engine-spec.md` |
| **Tier C · 家族基线** | 其余约 300 | 56 个视觉家族；保证正确、清晰、不穿帮；与 Hero 共享印版基调 | 徽章 ≤64px；剧场不黑团、不重复、不无限循环；全量回归 |

## 3. Gate（每道门都必须是可验收的）

### Gate 0 · Pilot 1（当前）

- 12 个主题 / 14 个事件条目（含 1945 日本组）。
- 14/14 打开、16 秒清理、390×844 无溢出、60fps、无回归。
- 资源版本 `20261107j`；提交 `5a76e2e`（本地，待推送）。
- 状态：**已满足**；线上仍为 v1，直到 GitHub Desktop 推送。

### Gate 1 · 30 个 Hero

- 在 Pilot 1 基础上增加 18 个，达到 30 个主题（32 个事件条目）——**数量已达成**。
- 质量：当前均分 4.06（2A/2B 4.08、2C 4.06），**未达 4.5**；待统一 texture pass。
- 质量：rubric 平均 ≥4.5；版画质感 ≥4；构图去重通过。
- 产能：单场景 ≤1.5 个工作日（含评审）。
- 性能：中端手机 60fps，低端 ≥30fps；单场景首帧 <200ms。
- 未达标：停在 30，不扩到 60。

### Gate 2 · 30–60 选项

只有满足以下条件才讨论 60：

- 混合资产管线（代码 + 纹理图章/栅格）稳定；单场景资源 <150KB。
- 有第二个人能按风格指南独立产出并通过评审。
- 移动端仍满足帧率与加载预算。

否则 30 就是上限。

### Gate 3 · Tier B 100–150

- 先做 3 个家族 × 5 个变体试点。
- 同家族 A/B 盲测 7/10 可区分；不重复标题；无穿帮。
- 通过后再扩到 100–150；不手工重画。

### Gate 4 · Tier C 家族基线

- 56 家族统一印版基调、线宽、纸纹、人物比例。
- 468 个非英雄事件全量回归：徽章、剧场、贸易 LOD、战斗上限、地区导航、面板滚动、台湾省数据。

### Phase 1 · 规范（本组文档）

- `hero-art-direction.md`：风格、线质、材质、构图、验收 rubric。
- `hero-selection-matrix.md`：24 选 18，3 批 × 6。
- `variant-engine-spec.md`：Tier B 参数、数据 schema、QA、试点。
- 决定 Tier C 的基线升级方式。

### Phase 2 · 下一批 18（3 批 × 6）

> 进度：2A、2B、2C 各 6 个均已完成结构复审（2A/2B 4.08、2C 4.06，见 `docs/hero-2*-review.md`），当前 **30 个主题 / 32 个事件条目**；数量达到 Gate 1，下一步统一 texture pass 后复评 4.5。

- 2A 古代轴心：吉萨、汉谟拉比、雅典民主、秦统一、孔雀王朝、丝绸之路。
- 2B 中世纪交流：希吉拉、成吉思汗、马里、婆罗浮屠、特诺奇蒂特兰、毛利抵达。
- 2C 早期现代与全球：古腾堡、达伽马、印加、法国大革命、印巴分治、万维网。
- 每批 6 个，做完一次设计评审；目标 30 个 Hero。

### Phase 3 · Tier B 100–150

- 3 家族 × 5 变体试点（建议：modern-founding、siege、caravel）。
- 参数引擎上线；再做 100–150 个变体。
- 不改变 `data/scene_variants.json` 的 482 条家族映射；变体是可选覆盖。

### Phase 4 · Tier C 家族基线

- 给地图剧场加轻量印版基调（底部压重、暖暗角、细刻线）。
- 56 家族统一线宽/纸纹/人物比例；全量回归。
- 解决“12 新、470 旧”的视觉断层。

### Phase 5 · 审计

- 真实设备帧率、加载、内存。
- 历史考据抽查（每场景 3–5 个细节）。
- 多语言标签、无障碍、版权/来源。

## 5. 工作流

| 工作流 | 负责内容 | 产出 |
|---|---|---|
| 美术方向 | 色板、线质、材质、构图规则 | `hero-art-direction.md` |
| Hero 场景 | 12 → 30 独立插画 | `js/hero-scenes.js` + 评审截图 |
| 变体引擎 | Tier B 参数与生成 | `variant-engine-spec.md` + 参数数据 |
| 家族基线 | 56 家族印版升级 | `js/theatre.js` 家族绘制 |
| 性能/移动 | 帧率、加载、DPR | 性能报告 |
| 历史 QA | 考据、标签、年份 | 抽查表 |
| 发布 | 版本、缓存、清单 | release commit |

## 6. 指标

- **质量**：rubric 平均分；版画质感分；构图去重（与同家族/同批场景的轮廓相似度）。
- **可辨识度**：去标签盲测，7/10 能说出事件或地域。
- **产能**：单场景人日；返工率。
- **性能**：中端机 fps、最大帧、首帧、内存。
- **资源**：单场景代码/栅格体积；总加载。
- **回归**：14/14、16 秒、LOD、战斗上限、台湾、面板、地区导航。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 范围膨胀到 60+ | Gate 1/2；先 30；未达标不加 |
| 风格漂移 | 风格指南 + 每批评审 + A/B |
| 移动端变慢 | 帧预算、DPR 上限、按需加载、离屏缓存 |
| 史实错误 | 每场景 3–5 条可核对细节；不编造 |
| 单人瓶颈 | 文档化、笔刷库、模板化参数（仅 Tier B） |
| 版权/来源 | 只用自有绘制/公版参考；记录来源 |
| 缓存旧资源 | 每次发布 bump `?v=`；发布清单检查 |
| “12 新、470 旧” | Phase 4 家族基线；先加轻量印版基调 |
